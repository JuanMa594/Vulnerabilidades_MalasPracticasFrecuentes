V01 · Arranque sin guardia Sin if __name__ == "__main__"

Este fallo no tiene formulario: está en la estructura del archivo app.py. Aquí se explica qué provoca y cómo comprobarlo.

Qué está mal

El servidor se arranca en el nivel superior del módulo, sin protegerlo con la guardia if __name__ == "__main__":.

{% raw %}
# inseguro/app.py (al final del archivo, sin guardia)
print("[inseguro] módulo cargado: arrancando el servidor...")
app.run(host=..., port=...)
{% endraw %}

Qué pasa por debajo

Al importar un módulo, Python ejecuta todo su nivel superior. Como app.run() está suelto, cualquiera que haga from inseguro.app import app —un servidor de producción como gunicorn, o una prueba— no obtiene el objeto app: en su lugar arranca el servidor de desarrollo y el programa queda colgado ahí. Además, cualquier efecto secundario del nivel superior (aquí un print; en un caso real, migraciones o conexiones) se dispara sin querer.

Cómo verlo logs del contenedor

  1. Mira el arranque del contenedor: {% raw %}
    rtk docker compose -f inseguro/compose.yml --env-file inseguro/.env.example logs web | head
    {% endraw %} Verás impresa la línea [inseguro] módulo cargado: arrancando el servidor...: es un efecto secundario que ocurrió solo por cargar el módulo.

Cómo verlo terminal, desde la raíz del repo

El comando se corre desde la raíz del proyecto (la carpeta que contiene inseguro/ y seguro/), y con uv run para usar el entorno que tiene Flask. Importar la app insegura arranca el servidor y se queda colgado (corta con Ctrl+C):

{% raw %}
uv run python -c "import inseguro.app"
# [inseguro] módulo cargado: arrancando el servidor de desarrollo...
#  * Running on http://127.0.0.1:8000   ← ¡solo por importarlo!  (Ctrl+C para salir)
{% endraw %}

La app segura, en cambio, se importa al instante sin arrancar nada:

{% raw %}
uv run python -c "import seguro.app"   # termina de inmediato, no arranca el servidor
{% endraw %}

Ojo: debe ser desde la raíz. Si lo corres dentro de inseguro/, falla con ModuleNotFoundError: No module named 'inseguro', porque desde ahí ya no existe esa carpeta.

Qué tan grave es Media

No es un agujero de seguridad directo, pero rompe las pruebas, impide desplegar con un servidor de producción y hace imposible reutilizar el módulo. Es la mala práctica más común al empezar, y la raíz de bugs difíciles de entender.

Cómo se arregla

En la versión segura, el arranque va protegido: {% raw %}
if __name__ == "__main__":
    app.run(host=..., port=...)
{% endraw %} Así el módulo se puede importar sin efectos y el servidor solo arranca cuando se ejecuta a propósito.
