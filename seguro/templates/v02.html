Qué está mal

La fórmula del usuario se pasa directo a eval().

{% raw %}
resultado = repr(eval(formula))   # 'formula' viene del usuario
{% endraw %}

Qué pasa por debajo

eval() compila y ejecuta el texto como código Python, con todos los permisos del proceso. __import__('subprocess').check_output(['id']) importa el módulo subprocess y ejecuta el comando id del sistema operativo. Cualquier expresión vale: leer variables, abrir archivos, ejecutar comandos.

Cómo verlo la página + el contenedor

  1. La página muestra la salida del comando: uid=1000(app) gid=1000(app)....
  2. Confirma quién lo ejecuta: {% raw %}
    rtk docker compose -f inseguro/compose.yml --env-file inseguro/.env.example exec web whoami
    {% endraw %} (responde app: el atacante ejecuta como ese usuario dentro del contenedor).
  3. Lista el sistema de archivos del contenedor con __import__('os').listdir('/').

Detalles que verás para no confundirse

  • La salida aparece como b'uid=1000(app)...\n': la b'...' significa que son bytes (lo que devuelven los comandos) y \n es el salto de línea. Es normal.
  • Si usas __import__('os').system('id'), la página muestra solo 0 (el código de salida). La salida real del comando se va a los logs del contenedor: {% raw %}
    rtk docker compose -f inseguro/compose.yml --env-file inseguro/.env.example logs web | grep uid=
    {% endraw %} Por eso el ejemplo usa check_output, que sí devuelve la salida y se ve en la página.
  • eval() evalúa una sola expresión, no instrucciones: escribir import os da SyntaxError. Por eso el ataque usa __import__('subprocess') (una expresión) en vez de import subprocess.

Qué tan grave es Crítica

Ejecución de código arbitrario (RCE): el atacante controla el proceso. Aquí el daño quedó contenido porque el contenedor corre como usuario sin privilegios (app), no root.

Cómo se arregla

Nunca eval() sobre entrada externa. Para "solo cuentas" se usa ast.literal_eval (solo literales) o un parser/validador propio. Para comandos, nunca armar cadenas: subprocess con lista de argumentos y sin shell=True.
