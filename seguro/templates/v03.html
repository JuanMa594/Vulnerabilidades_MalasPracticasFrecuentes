V03 · Pasarela de pagos Secreto en el código

Esta pantalla muestra la clave que la app usa para cobrar. Está escrita dentro del código (app.py), no en una variable de entorno. Por eso aparece aquí, y también la vería cualquiera que lea el repositorio o su historial.

Clave que la app tiene guardada:

API_KEY_PASARELA = {{ api_key }}

Qué está mal

El secreto es una constante en el código fuente.

{% raw %}
API_KEY_PASARELA = "sk-FALSO-pagos-9c8b7a6d5e4f3210"
{% endraw %}

Qué pasa por debajo

Un secreto en el código viaja en cada copia del repositorio y queda registrado en el historial de git para siempre: aunque después lo borres del archivo, sigue en los commits anteriores. Cualquiera con acceso al repo (o a un backup, o a un fork) lo tiene.

Cómo verlo terminal / git

  1. Buscarlo en el código: {% raw %}
    rtk grep -rn "sk-FALSO" inseguro/
    {% endraw %}
  2. Verlo en el historial (sigue ahí aunque lo borres del archivo): {% raw %}
    rtk git log -p -- inseguro/app.py
    {% endraw %}

Detalles que verás para no confundirse

  • La página muestra sk-FALSO-pagos-9c8b7a6d5e4f3210 sin comillas; en el código es un texto de Python, por eso en la fuente aparece entre comillas ("sk-FALSO-..."). Es el mismo valor.
  • La clave lleva FALSO a propósito: es de demostración y no cobra de verdad. En un caso real ahí estaría la clave verdadera y el fallo sería idéntico.
  • Aquí no hay nada que mirar en pgAdmin: el secreto no está en la base, está en el código.

Qué tan grave es Alta

Quien vea el secreto puede usar el servicio (aquí, cobrar con la pasarela). Rotarlo obliga a cambiar la clave en el proveedor y, para borrar el rastro, reescribir el historial de git.

Cómo se arregla

Leer la clave de una variable de entorno (os.environ["API_KEY_PASARELA"]) y ponerla en .env, que está fuera de git (igual que las credenciales de la base en este mismo proyecto).
