Qué estaba mal

La versión insegura usaba pickle.loads(), que puede ejecutar código al deserializar.

Cómo se corrigió

Se usa JSON, un formato que solo representa datos (números, textos, listas, diccionarios) y nunca ejecuta funciones. {% raw %}
objeto = json.loads(datos)   # solo lee datos; no hay __reduce__ ni código
{% endraw %}

Cómo comprobarlo la página + el contenedor

  1. Pega el pickle de ataque (segundo ejemplo): antes ejecutaba id; aquí solo da un error de formato, sin correr nada.
  2. Confirma que nada se ejecutó (no aparecen archivos nuevos): {% raw %}
    rtk docker compose -f seguro/compose.yml --env-file seguro/.env.example exec web ls -l /tmp
    {% endraw %}

Detalles que verás para no confundirse

  • Con el pickle de ataque verás un error tipo JSONDecodeError: Expecting value...: es json.loads() diciendo "esto no es JSON". No ejecutó nada; solo rechazó el dato.
  • El carrito normal devuelve {'producto': 'FE-001', 'cantidad': 2}: un diccionario de Python leído como datos.

Qué tan grave era Crítica

Con pickle, ejecución de código con solo enviar datos. Con JSON, ese riesgo desaparece.
