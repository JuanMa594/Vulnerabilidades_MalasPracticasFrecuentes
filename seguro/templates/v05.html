V05 · Restaurar carrito Deserialización (corregida)

Pega un "carrito guardado" y el backend lo restaura con json.loads(). JSON solo describe datos: leerlo nunca ejecuta código. Prueba el carrito normal, y luego el carrito de ataque de la versión insegura: aquí no ejecuta nada, solo da un error de formato.

1. Carrito normal (JSON):

{"producto": "FE-001", "cantidad": 2}

2. El carrito de ataque de la versión insegura (base64 con un pickle): pégalo y verás que aquí no ejecuta nada, solo falla al no ser JSON válido:

gAWVKwAAAAAAAACMCnN1YnByb2Nlc3OUjAxjaGVja19vdXRwdXSUk5RdlIwCaWSUYYWUUpQu

Qué estaba mal

La versión insegura usaba pickle.loads(), que puede ejecutar código al deserializar.

Cómo se corrigió

Se usa JSON, un formato que solo representa datos (números, textos, listas, diccionarios) y nunca ejecuta funciones. {% raw %}
objeto = json.loads(datos)   # solo lee datos; no hay __reduce__ ni código
{% endraw %}

Cómo comprobarlo la página + el contenedor

  1. Pega el carrito de ataque (2): antes ejecutaba id; aquí solo da un error de formato, sin correr nada.
  2. Confirma que nada se ejecutó (no aparecen procesos ni archivos nuevos): {% raw %}
    rtk docker compose -f seguro/compose.yml --env-file seguro/.env.example exec web ls -l /tmp
    {% endraw %}
