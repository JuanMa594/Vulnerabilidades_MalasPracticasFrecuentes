V08 · Cotización temporal Mutable por defecto

Agrega un producto a una cotización que debería empezar vacía en cada visita. Pero la función usa cotizacion=[] como valor por defecto, y esa lista se comparte entre llamadas. Agrega martillo, luego taladro, y verás que la lista crece en vez de reiniciarse.

{% if item %}

Cotización que devolvió el backend:

{{ cotizacion }}

Debería tener solo {{ item }}. Si tiene más, son de peticiones anteriores.

{% endif %}

Qué está mal

El valor por defecto de un parámetro es una lista (un objeto mutable).

{% raw %}
def agregar_a_cotizacion(item, cotizacion=[]):
    cotizacion.append(item)
    return cotizacion
{% endraw %}

Qué pasa por debajo

El [] por defecto se crea una sola vez, cuando se define la función, y esa misma lista se reutiliza en todas las llamadas. Como el servidor es un proceso que vive entre peticiones, la lista va acumulando lo de cada visita, incluso de personas distintas.

Cómo verlo la página (memoria del proceso)

  1. Agrega martillo. Luego, en otra petición, agrega taladro: la cotización muestra los dos, no solo el último.
  2. Sigue agregando: nunca se reinicia. No es de base de datos: vive en la memoria del proceso, por eso se observa recargando la página.

Qué tan grave es Media

No es un agujero de seguridad clásico, pero mezcla datos entre usuarios y peticiones (una persona ve ítems de otra) y produce resultados incorrectos. Es un bug clásico que sorprende a todos.

Cómo se arregla

Usar None como valor por defecto y crear la lista dentro: {% raw %}
def agregar_a_cotizacion(item, cotizacion=None):
    if cotizacion is None:
        cotizacion = []
    cotizacion.append(item)
    return cotizacion
{% endraw %}
