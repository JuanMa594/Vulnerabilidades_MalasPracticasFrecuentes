Qué está mal

La consulta se construye con un f-string que mete el texto del usuario dentro del SQL.

{% raw %}
sql = f"SELECT * FROM productos WHERE nombre ILIKE '%{termino}%'"
{% endraw %}

Qué pasa por debajo

Tu texto deja de ser un dato y pasa a ser parte de la instrucción. Con ' OR '1'='1 el filtro se vuelve siempre verdadero y devuelve todo. Peor: con UNION se leen otras tablas, como usuarios (¡con las contraseñas!).

Cómo verlo pgAdmin + la página

  1. En el Query Tool de pgAdmin, corre la misma consulta que arma la app con ' OR '1'='1: {% raw %}
    SELECT * FROM productos WHERE nombre ILIKE '%' OR '1'='1%';
    {% endraw %} Devuelve los 18, no uno.
  2. Para robar contraseñas, pulsa Ejecutar en el ejemplo UNION de arriba (o pégalo en el buscador): {% raw %}
    zzz' UNION SELECT id, nombre, password, rol, 0, 0, '' FROM usuarios --
    {% endraw %} Devuelve 2 filas con las credenciales (admin-secreto-demo y cajero123).
  3. Compáralo en pgAdmin con lo que había: {% raw %}
    SELECT nombre, password, rol FROM usuarios;
    {% endraw %}

Detalles que verás para no confundirse

  • La tabla de resultados miente en las cabeceras: UNION cuadra las columnas por posición, no por nombre. Como el ataque pide id, nombre, password, rol, la contraseña sale bajo la cabecera "nombre" (admin-secreto-demo), el usuario bajo "sku" (admin) y el rol bajo "categoría". No es un fallo de la tabla: es que la fila viene de usuarios, no de productos.
  • Las columnas "precio" y "stock" salen en 0 y "imagen" sale vacía porque el ataque rellena esas posiciones con 0, 0, '' solo para completar las 7 columnas que espera la consulta original.
  • El -- del final (con un espacio detrás) es un comentario de SQL: descarta el %' que la app pega después de tu texto, para que la consulta no dé error de sintaxis.

Qué tan grave es Crítica

Permite leer y alterar toda la base, incluidas credenciales. Es una de las vulnerabilidades más explotadas del mundo real.

Cómo se arregla

Consulta parametrizada: el texto viaja aparte y el driver nunca lo trata como SQL. {% raw %}
cur.execute(
    "SELECT * FROM productos WHERE nombre ILIKE %s",
    (f"%{termino}%",),
)
{% endraw %}
