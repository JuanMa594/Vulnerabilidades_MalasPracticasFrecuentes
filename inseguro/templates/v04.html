V04 · Buscar productos SQL Injection

Busca un producto por su nombre. La consulta se arma pegando tu texto dentro del SQL, así que no solo buscas: puedes cambiar la consulta. Prueba martillo, luego ' OR '1'='1, y por último el ataque de abajo para robar contraseñas.

Qué está mal

La consulta se construye con un f-string que mete el texto del usuario dentro del SQL.

{% raw %}
sql = f"SELECT * FROM productos WHERE nombre ILIKE '%{termino}%'"
{% endraw %}

Qué pasa por debajo

Tu texto deja de ser un dato y pasa a ser parte de la instrucción. Con ' OR '1'='1 el filtro se vuelve siempre verdadero y devuelve todo. Peor: con UNION se leen otras tablas, como usuarios (¡con las contraseñas!).

Cómo verlo pgAdmin

  1. En el Query Tool de pgAdmin, corre la misma consulta que arma la app con ' OR '1'='1: {% raw %}
    SELECT * FROM productos WHERE nombre ILIKE '%' OR '1'='1%';
    {% endraw %} Devuelve los 18, no uno.
  2. Para robar contraseñas, pega esto en el buscador de arriba: {% raw %}
    zzz' UNION SELECT id, nombre, password, rol, 0, 0, '' FROM usuarios --
    {% endraw %} En la columna "nombre" verás los usuarios y donde iría el nombre saldrá la contraseña (admin-secreto-demo).
  3. Compáralo en pgAdmin con lo que había: {% raw %}
    SELECT nombre, password, rol FROM usuarios;
    {% endraw %}

Qué tan grave es Crítica

Permite leer y alterar toda la base, incluidas credenciales. Es una de las vulnerabilidades más explotadas del mundo real.

Cómo se arregla

Consulta parametrizada: el texto viaja aparte y el driver nunca lo trata como SQL. {% raw %}
cur.execute(
    "SELECT * FROM productos WHERE nombre ILIKE %s",
    (f"%{termino}%",),
)
{% endraw %}
