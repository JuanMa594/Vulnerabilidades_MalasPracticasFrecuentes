V05 · Restaurar carrito Deserialización insegura

Pega un "carrito guardado" (texto en base64) y el backend lo restaura con pickle.loads(). El problema: pickle no solo lee datos, también puede ejecutar código mientras deserializa.

Qué está mal

Se deserializan con pickle datos que llegan de afuera.

{% raw %}
objeto = pickle.loads(base64.b64decode(datos))   # 'datos' viene del usuario
{% endraw %}

Qué pasa por debajo

Al deserializar, pickle reconstruye objetos y para eso puede llamar funciones (método __reduce__). El carrito de ataque fue preparado para que, al reconstruirse, ejecute subprocess.check_output(['id']): corre el comando y el "objeto" resultante es su salida. Es decir, el código corre antes de que veas ningún carrito.

Cómo verlo la página + el contenedor

  1. Pega el carrito de ataque (2) y restaura: la página muestra uid=1000(app)..., la salida real del comando.
  2. Un payload podría dejar rastro (crear un archivo). Revisa dentro del contenedor: {% raw %}
    rtk docker compose -f inseguro/compose.yml --env-file inseguro/.env.example exec web ls -l /tmp
    {% endraw %}

Qué tan grave es Crítica

Ejecución de código con solo enviar datos. Aparece cada vez que se aceptan objetos serializados (cookies, colas, archivos "de configuración") de origen no confiable.

Cómo se arregla

No usar pickle con datos externos. Usar un formato que solo describe datos, como JSON: json.loads(datos) nunca ejecuta código, solo lee valores.
